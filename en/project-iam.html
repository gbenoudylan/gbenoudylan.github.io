Automating access reviews

At MTN Côte d'Ivoire, checking that each employee only has access to the tools they need was done entirely by hand. I designed the application that replaces that work.

  • −98 %time per review: 3 minutes instead of 2 hours
  • 6,000+risky accounts flagged in one month
  • 20automated controls, up from 10 manual checks
  • 550+automated tests, all passing

01

The problem

An access review means checking, account by account, who can do what. Each system exports its accounts in its own format, and everything had to be cross-checked by hand. A review took 2 hours on average.

02

The context

Data Protection & IAM internship at MTN Côte d'Ivoire, in the Enterprise Information Security & IT Governance team. The operator has more than 17 million subscribers: its employees' access rights are a first-order security concern.

I ran the project end to end, almost independently. When an unexpected data quality issue came up, I reorganised priorities and delivered the tool on time.

03

The technical thinking

Rather than imposing an input format, the tool reads exports as they come: CSV, Excel, LDIF, JSON, PDF and six other formats, eleven in total.

It then detects unused accounts, former employees who are still active and dangerous combinations of rights, and ranks each account by criticality from 0 to 100 so the team knows where to start.

04

The chosen architecture

The reading module is generic enough to have been reused unchanged in a second tool, the vulnerability prioritisation one.

05

Difficulties and solutions

Difficulty 1

HTML files: a shifted row

Solution

The reading library already applied its own header detection, which clashed with mine. I unified the processing entry point upstream, whatever library is used.

Difficulty 2

LDAP dates: dormant accounts going undetected

Solution

The native date format of LDAP directories (Generalized Time) wasn't recognised by any generic parser. I added dedicated handling for that format, with an automatic fallback to the generic parser.

Difficulty 3

No HR status: invisible leavers

Solution

Some exports, LDAP ones in particular, carry no employment status at all. I added a module that cross-checks them against a complementary HR source.
